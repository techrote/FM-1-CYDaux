# Integration contract

Target: original ESP32-2432S028R, 320 × 240 landscape, ILI9341 and XPT2046.
No physical hardware is available. Simulator results are not hardware acceptance.

## Shared core

UI consumes UiModel, emits UiAction, and draws via portable Canvas. Hardware and
simulator compile the same C++ core, renderer and hit testing. Controller handles
musical state; platform adapters handle connection and setup. A successful adapter delivery completion calls didSend. Pending/Sent are not device-confirmed state; a TCP write is not proof of USB delivery or instrument acceptance. The bridge does not send a success acknowledgement for MIDI frames. Mock bridge data
is labelled Demo; reconnect/profile changes clear stale values and held notes.

## Wi-Fi bridge v1

TCP port 45821, UTF-8 JSON objects separated by LF. Line cap 2048 bytes excluding LF.
One complete MIDI message per frame, at most 256 bytes. One authenticated client.
Client hello: {"type":"hello","protocol":1,"token":"..."}
Server hello: {"type":"hello","protocol":1,"mode":"mock","ready":true,"name":"Demo FM-1"}
mode is mock or midi. MIDI both ways: {"type":"midi","data":[176,74,64]}.
Client ping {"type":"ping","id":123}, server pong echoes id. Ping every two seconds;
six seconds of idle expires the session and releases used-channel notes.
Backend status: {"type":"status","ready":false,"reason":"MIDI disconnected"}.
Errors: {"type":"error","message":"..."}. Optional client {"type":"profile","id":"sloop"}
changes mock behavior only. Never installs or changes actual instrument firmware.

No replay after reconnect. Bounded queues. No arbitrary first MIDI-port selection.
Loopback is default; LAN listening is explicit. Token is local access control,
not encryption. No firmware updater or flash commands are generated by the app.

SLOOP LIVE requires validated SLOOP identity, supported layout, INFO protocol >=12 and the Wi-Fi/USB bridge. Remote transport also requires an initial valid LIVE reply. See [firmware audit](firmwares.md) for the exact current layout and compatibility gates.
Unknown firmware stays controller-only. Direct BLE carries performance messages;
SysEx is not implemented on the direct BLE path in this version.
